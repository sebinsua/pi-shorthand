# Edit failure audit

## Implemented follow-up (2026-09-21)

- **API shape:** `sg.find`, `sg.one`, `sg.rewrite` and `grit` accept `sg.file()` targets and mixed arrays.
  File targets select explicit files, including ignored files inside the workspace; search reads current
  source and rejects missing targets. Apply eligibility is unchanged. The original recorded header program
  now passes independent verification without correcting its arguments.
- **API shape and warning:** Grit expands glob inputs and warns without invoking the backend when the entire
  selection is empty. Existing directory discovery remains delegated to Grit.
- **Type diagnostics:** `api.d.ts` derives injected global types from the implementation. Compile-time
  regressions accept supported composition and reject invented helpers, invalid scopes and conflicting
  placement destinations. These enable external checking; execution still does not automatically type-check.
- **Skill references:** only API-contract updates remain. The speculative method/body and Grit rewrite
  examples were removed; no prompting fix has been established for those strategy failures.
- **Already addressed:** verification stays outside writes, CLI availability is documented, and contextual
  pattern errors retain their actionable correction. No noisy brace-search heuristic or automatic retry was added.

The Grit backend panic itself is not fixed; the working split-query alternative is documented. The analysis
below records the original failures and the reasoning behind these changes. No performance improvement is
claimed without a subsequent model comparison.

Classify an observed failure before changing the tool: could the existing API express the edit, could a
specific diagnostic detect the mistake, and would instructions or a different public API prevent it?
These are overlapping questions. A runtime error, static type error, pattern diagnostic and application
test failure are different kinds of feedback.

This audit groups repeated occurrences across the recorded pilots, guidance comparisons and recovery runs.
It includes successful invocations that needed a source repair. Links point to local, ignored benchmark
artifacts; the decisions and existing replay programs remain in version control. Proposed warnings and API
changes below have not been implemented or benchmarked. No new model calls were made for this audit.

## Resulting improvement priorities

1. Make the actual editing API types available to program tooling. The path/placement failure is a concrete
   acceptance case for type diagnostics; declarations alone do not mean generated programs are checked.
2. Resolve the path/placement composition mismatch deliberately. Retain the new runtime errors in the meantime.
3. Add only the missing structural idioms to reference guidance: contextual matching, node fields and narrow
   captured-node edits. Existing replays establish that these operations work; model uptake is still unproven.
4. Treat Grit path handling and the backend panic as separate implementation issues. Neither is solved by a
   blanket instruction to prefer GritQL.

Before implementing a lint warning, specify the offending expression, required information, useful message,
and a valid counterexample that must remain quiet. Prefer deterministic API/type diagnostics; do not present
heuristics as correctness checks. This audit adds no automatic validation gate and changes no rollback mode.
